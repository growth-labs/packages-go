# Go OpenAuth Consumer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and release the shared Go OpenAuth client, conformance suite, HTTP middleware, documentation, and runnable example.

**Architecture:** A standard-library `auth.Client` owns immutable OAuth configuration, transport, JWKS cache, and HTTP adapters. OAuth token operations share one secret-resolution and form-post path; verification parses ES256 JWT/JWKS directly and materializes a typed principal. Issuer fixtures are embedded as a pinned versioned snapshot and tested through `testkit`.

**Tech Stack:** Go 1.26.0/toolchain 1.26.6, `net/http`, `crypto/ecdsa`, `crypto/sha256`, `encoding/json`, `github.com/growth-labs/packages-go/testkit`.

## Global Constraints

- Module path: `github.com/growth-labs/packages-go/auth`.
- Browser issuer and optional internal issuer remain distinct.
- PKCE method is exactly S256; RFC 8707 `resource` is sent on authorize, token exchange, and refresh.
- Access-token TTL fixture is 900 seconds; refresh-token TTL fixture is 2,592,000 seconds; refresh reuse grace is 600 seconds inclusive.
- Session cookies are `HttpOnly; Secure; SameSite=Lax; Path=/` and use the TypeScript suffixes `_at` and `_rt`.
- No secrets, usable tokens, production writes, or mutating live issuer calls.
- Only one explicit test file under active edit is run locally; fleet CI runs the full suite.
